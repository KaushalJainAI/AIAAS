# How OpenCode (anomalyco/opencode) renders LLM output: markdown, code, streaming, sources

**Repo / revision inspected:** `github.com/anomalyco/opencode`, branch **`dev`**, commit **`e56eff2bc01649b3aa21224876b8874e77dea4b0`** ("feat(core): tell agents when they are in a fork (#63235)", committed 2026-11-11 08:41:50 +0100). Inspected 2026-11-11 by shallow clone + sparse checkout of `packages/{patchmark,session-ui,tui,ui,latex,merman}`. All file links below pin that SHA.

**Headline architecture (one paragraph, for orientation).** The desktop/web transcript does **not** hand raw LLM text to `marked`. A custom streaming markdown engine, `@opencode/patchmark`, incrementally parses the growing text into a list of **blocks** with stable IDs and emits a minimal patch list per delta (`append` / `replace` / `finalize` / `truncate`). `packages/session-ui/src/components/markdown-stream.ts` converts those blocks into three render modes — `full` (settled), `live` (streaming tail, with healed tail text), `code` (fenced code / mermaid, bypassing markdown entirely) — and sends them to a **web worker** which does two jobs: `marked` (+KaTeX +`@pierre/highlights`) → sanitized HTML for prose blocks, and `@pierre/highlights` `LiveTokenizer` → stable/unstable token arrays for code blocks. The main thread then does surgical DOM updates keyed by block, and a Solid `createStore`+`reconcile` renderer does word-level animation on live blocks. DOMPurify sanitizes every HTML string, with hooks that convert local file links/images into inert `data-local-*` attributes.

## Q1. `packages/patchmark/src/heal.ts` — what "heal" actually repairs, and the algorithm

### Takeaway
`heal.ts` heals **only the inline tail** of one block's text (a paragraph, a heading, or the last table row): it closes open emphasis/strikethrough/code-span markers that have content after them, *deletes* a dangling opener that has nothing after it yet, and rewrites an unfinished `[label](url…` link into just its label. It never touches fences, tables' structure, or lists — those are handled structurally by the block parser. `computeTailHeal` returns a `{strip, append}` edit rather than a new string, so the same edit can be applied to both `raw` and `liveRaw`.

### Cited Findings
- The module's stated purpose is exactly the "half-written `**` renders as `****` (a rule)" problem: `// Streaming tail healing: close inline markers that are still open at the end of the block being written, // and hide markers that have nothing after them yet, so a half-written `**` never renders as `****` (a rule).` — [patchmark/src/heal.ts#L1-L2](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L1-L2)
- The public API is a pure edit descriptor: `interface TailHeal { strip: number; append: string }`, `computeTailHeal(input)`, `applyTailHeal(text, heal)`, and a convenience `healStreamingInline(raw)`. `applyTailHeal` always measures from the **right-trimmed** text: `const end = rtrimLength(text); return text.slice(0, Math.max(0, end - heal.strip)) + heal.append` — [heal.ts#L4-L9, L235-L239](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L235-L239)
- Documented behaviour of the wrapper: `` `**bold` → `**bold**`, `` `code `` → `` `code` ``, `[label](https://…` → `label`, and a trailing `**` with nothing after it yet is hidden rather than doubled.`` — [heal.ts#L241-L251](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L241-L251)
- **Rule 1 — unfinished link/image at the very end.** It finds the last unescaped `[`, matches `reLinkTail = /(!?)\[([^\]\n]*)\]\(([^)\n]*)$/`, and replaces the whole match with the label text (`m[1] ? "" : m[2]`): `heal = { strip: matchLen, append: replacement }`. For an image (`![alt](url…`) the replacement is the empty string; for a link it is the label — [heal.ts#L14, L56-L66](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L56-L66)
- **Rule 2 — one left-to-right scanner over code spans, math, and emphasis.** The scan skips over closed math (`reInlineDollarMath` / `reInlineParenMath`, the same regexes used by the marked KaTeX extension) and over backslash escapes (`i += 2`), tracks backtick runs as `codeOpen`, and pushes/pops `*`, `_`, `~` runs on a stack with a CommonMark-ish openness test: `canOpen = !isSpace(next) && !(isUnderscore && isAlnum(prev)) && !(isSingleStar && isAlnum(prev) && !wordHadEm)`, `canClose = !isSpace(prev) && !(isUnderscore && isAlnum(next))`. Runs of `***` are pushed as two openers (`len 2` then `len 1`); `~~~` runs longer than 2 are ignored — [heal.ts#L68-L183](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L68-L183)
- **Rule 3 — code spans.** If the buffer ends inside a backtick run: when the opener *is* the end of the text (`codeOpen.start + codeOpen.len >= nonSpaceEnd`) the opener is **stripped**; otherwise it **appends** the same number of backticks and sets `codeClosed = true` (so rule 5's space-trimming is skipped, because a code span's closer must not be preceded by added spaces) — [heal.ts#L185-L197](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L185-L197)
- **Rule 4 — close innermost-first, or hide.** Iterating the stack from the top: `if (open.after >= nonSpaceEnd)` (nothing but whitespace follows the opener) → the opener is **removed** together with preceding spaces/tabs (`let cut = open.start; while (cut > 0 && (text.charCodeAt(cut - 1) === 0x20 || ... 0x09)) cut--; strip = n - cut`), but only while `append === ""`; otherwise (`open.start >= limit`) it is skipped. Openers that *do* have content after them get their marker appended: `append += String.fromCharCode(open.ch).repeat(open.len)` — [heal.ts#L199-L223](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L199-L223)
- **Rule 5 — closers must hug the text**: "drop trailing spaces before appending" (`if (append && !codeClosed) { let cut = n - strip; while (cut > 0 && isSpace(...)) cut--; strip = n - cut }`) — [heal.ts#L225-L230](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L225-L230)
- **Composition.** Link healing (rule 1) and inline healing (rules 2-5) are merged by `compose(a, b)`, which rebases `b.strip` against `a.append` so the two edits never conflict — [heal.ts#L30-L35, L232](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/heal.ts#L30-L35)
- **Where heal is applied, and to what.** In `PatchmarkStream.buildTail`, heal is computed only when the fork's tip is a `paragraph`, `heading` or `table`, and for a table only on the *last* row: `const content = tip.type === "table" ? (tip.rows[tip.rows.length - 1] ?? "") : tip.content`. The result is applied to `node.content` for paragraph/heading, to the last table row (`applyTailHeal(node.rows[node.rows.length - 1]!, ctx.heal!)`), and to the first paragraph of a task-list item; the healed string is also stored as `block.liveRaw` for the tail block — [patchmark/src/stream.ts#L574-L585, L634, L735-L745, L866-L868, L907](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L574-L585)
- **What heal explicitly does *not* do:** there is no fence logic in `heal.ts` (fence completeness is `node.fenceClosed` in `blocks.ts`); tables are never re-shaped (rows are appended and the last one healed); lists are never closed by heal — the *fork* is finished (`fork.finish()`), so the tail tree is structurally complete but flagged `streaming` — [patchmark/src/blocks.ts#L459-L484, L952-L957](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/blocks.ts#L459-L484); [stream.ts#L564-L572](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L564-L572)
- Test that pins the rule: `test("partial ** on the streaming tail never heals into **** or flashes as an <hr>")` and `test("heals incomplete emphasis, code spans, and links on the streaming tail")` — [patchmark/test/patchmark.test.ts#L53, L171](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/test/patchmark.test.ts#L171)

### Inferences
- Heal is a *render-time* transform on the tail only; because `computeTailHeal` returns offsets relative to the right-trimmed text and operates on a single "inline run", it cannot accidentally disturb already-closed spans earlier in the block — the scanner pops closed runs rather than rewriting them.
- Because the dangling-opener branch only triggers while `append === ""`, a trailing run like `**bold *ital` produces `**bold *ital*` plus `**`? No — order is innermost-first (`s = stack.length - 1 … 0`), so `*ital*` is appended first, then `**` is appended, yielding `**bold *ital***`, which is the minimal correct repair.

### Gaps
- The heuristic `canOpen`/`canClose` is *not* CommonMark's full left/right-flanking rule (no Unicode punctuation class, no "multiple of 3" rule); behaviour on pathological delimiter runs is only pinned by the linear-time tests (`<250ms`), not by spec examples. See [slow-inputs.test.ts](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/test/slow-inputs.test.ts).

## Q2. `stream.ts` / `blocks.ts` — block splitting, settling, stable vs live, pending markers

### Takeaway
`blocks.ts` is a **line-by-line port of commonmark.js 0.31.2** extended with GFM tables and `$$`/`$` display math, made *persistent*: each complete line is incorporated exactly once into a real tree, and the streaming tail is produced by **forking only the open spine** of that tree into a throwaway parser that is then `finish()`ed. `stream.ts` (`PatchmarkStream`) then decides which top-level nodes are "settled", converts nodes to a typed `BlockKind` AST, emits `MarkdownBlock`s with monotonic ids and a minimal `BlockPatch[]` diff, and holds back a bare trailing block marker for one frame so a `##` or `-` doesn't pop from paragraph to heading/list.

### Cited Findings
- **Parser provenance.** `// CommonMark 0.31.2 block parser: a line-by-line port of commonmark.js `blocks.js`, extended with GFM tables and // OpenCode's `$$`/`$` display-math blocks. The parser is persistent: complete lines are incorporated once, and the // streaming tail is produced by forking only the open spine (the open last-child chain) of the tree.` — [patchmark/src/blocks.ts#L1-L3](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/blocks.ts#L1-L3)
- **Forking.** `fork()` shallow-clones the document without children, then walks `src !== this.tip` cloning each last child (`shallowClone(child.children.length > 0)`), stopping at the tip; the fork sets `forkMode = true` so every node it creates or clones gets `forked = true` and is therefore never cached — [blocks.ts#L306-L330, L99-L128, L294-L304](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/blocks.ts#L306-L330)
- **Line ingestion.** `feedCompleteLines` scans for `\n`/`\r` terminators, and deliberately *defers* a lone trailing `\r` while streaming (`else if (streaming) break`); each line goes through `parser.incorporateLine`. `pushLine` records `lineStarts`, `lines` (without terminator) and `lineRaw` (with terminator) — [stream.ts#L504-L531](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L504-L531)
- **Settling rule (1): default `settleOnComplete: true`.** A unit settles as soon as the parser closed it: `if (open && !early) break`, where `open` is true if any child in `first..last` is still open. The exception is `early`: a lone open **heading or thematic break** at the tail settles immediately, because CommonMark already knows its extent: `const early = this.options.settleOnComplete && first === last && node.open && isLast && streaming && (node.type === "heading" || node.type === "thematic_break")` — [stream.ts#L297-L316](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L297-L316)
- **Settling rule (2): `settleOnComplete: false` (what session-ui uses).** Nothing settles until a *later visible* block begins: it searches `for (let m = last + 1; m < children.length; m++) if (!children[m].open && !children[m].defsOnly) hasVisibleAfter = true`; if nothing visible follows it additionally requires that the tail isn't a possible reference definition (`mayBeDef` fork check) before breaking — [stream.ts#L316-L336](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L316-L336). Option doc: "Settle top-level blocks as soon as CommonMark closes them, or wait until a later visible block begins" — [patchmark/src/types.ts#L138-L139](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/types.ts#L138-L139)
- **Stable vs live.** Settled blocks are never re-parsed: `settledCount` only grows, `settledOffset()` is `blocks[settledCount - 1].end`, and in step 3 the tail is reconciled index-by-index — if `prev.raw === block.raw && prev.liveRaw === block.liveRaw && prev.status === block.status && prev.defs === block.defs` the **previous object is reused by identity** (`block = prev`), otherwise a `replace` patch is emitted. Frame doc: "settled prefix references are preserved identically across frames" — [stream.ts#L375-L401, L212-L215](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L375-L401); [types.ts#L114-L127](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/types.ts#L114-L127)
- **Patch protocol.** `BlockPatch = {op:"append"} | {op:"replace", id, index} | {op:"finalize", id, index} | {op:"truncate", keepCount}`; `MarkdownBlock = {id, start, end, raw, status:"streaming"|"settled", kind, html?, defs?, liveRaw?}`; block ids are monotonic and a block keeps its id when it settles (`block.id = prev.id` then `finalize`) — [patchmark/src/types.ts#L87-L112](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/types.ts#L87-L112); [stream.ts#L380-L395](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L380-L395)
- **Pending markers.** `splitPendingMarker(text)` holds the last line back when it is *only* a bare opener, guarding `tailLine.length > 12`, and requires **all characters identical**: `#` up to 6, `` ` ``/`~` up to 3, everything else up to 2 (`-`, `*`, `_`, `$`, `=`), plus the literals `+`, `•`, `>`, `\[`, and `\d+` followed by nothing, `.` or `)`. Docstring: "If the last line holds only a bare block opener (`-`, `*`, `+`, `##`, `12.`, `>`, a bare triple-backtick fence, `$$`), hold that line back until its first content character or newline arrives. Prevents 1-frame paragraph-to-heading/list pops." — [stream.ts#L16-L65](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L16-L65)
- **Second pending-marker rule (always on).** Setext candidates are held even when `holdPendingMarkers` is false: `const RE_SETEXT_CANDIDATE = /^[ \t]*(?:-+|=+)[ \t]*$/` with the comment "A partial line that is only `-`/`=` … would turn the paragraph above into a setext heading for a frame" — [stream.ts#L67-L69, L274-L285](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L67-L69)
- **HTML grouping.** With `groupHtmlBlocks: true`, `groupEnd()` sums `htmlBalance` over consecutive `html_block` nodes and returns `-1` while the balance stays positive, which turns e.g. `<details>`…`</details>` into one `{type:"group", blocks}` display unit. Balance counts non-void open minus close tags, ignoring comments and `htmlBlockType <= 5` (raw-text blocks that already have terminators) — [stream.ts#L640-L660, L929-L944](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L929-L944)
- **Late reference definitions.** `backfillRefs` keeps `waiting: Map<label, Set<settledIndex>>` plus `provisionalRefs` for defs seen only in a fork, and re-converts just the affected settled blocks, patching or replacing only those: "Reference definitions that arrived after the blocks that use them: patch those blocks" — [stream.ts#L402-L493](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L402-L493)
- **Math disambiguation (reparse).** A `$$` block that never closes is not math: `unclosedMathAt` is recorded at finalize, and `reparse()` adds that line to `disallowMath` and re-reads the whole document with that opener disabled, dropping both caches — [blocks.ts#L562-L566, L773-L788](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/blocks.ts#L773-L788); [stream.ts#L533-L548](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/src/stream.ts#L533-L548)
- **Correctness evidence.** The package's own tests claim 100% conformance and streaming invariance: `test("passes all 652 CommonMark 0.31.2 spec examples (100%)")`, `test("passes all 24 GFM spec examples (tables, task lists, strikethrough, autolinks)")`, `test("streaming invariance: 1-char, seeded random, and token chunking across all 652 CommonMark + 24 GFM + transcripts")`, plus differential fuzzing `zero core CommonMark diffs across 5,000 seeded generated + spec-mutated cases` and `zero unexplained GFM diffs across 2,000 …` — [patchmark/test/commonmark-spec.test.ts#L91-L128](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/test/commonmark-spec.test.ts#L91-L128); [patchmark/test/fuzz-differential.test.ts#L5-L20](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/test/fuzz-differential.test.ts#L5-L20)
- **Linear-time guarantees** (relevant to "very large" inputs): `test("huge GFM table streamed row-by-row stays linear (<250ms for 1,000 rows)")`, `test("long * and _ delimiter runs and distinct unclosed backtick runs stay linear (<250ms)")`, `test("deeply nested blockquotes and lists stay linear (<200ms)")` — [patchmark/test/slow-inputs.test.ts#L4-L77](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/patchmark/test/slow-inputs.test.ts)
- **Why session-ui disables two of these knobs.** `createMarkdownStream({ gfm: true, math: true, heal: true, holdPendingMarkers: false, settleOnComplete: false, groupHtmlBlocks: true, renderHtml: false })` — [session-ui/src/components/markdown-stream.ts#L21-L31](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/components/markdown-stream.ts#L21-L31). ### Inferences
- Because the tail fork is `finish()`ed before conversion, "settled" is a *projection* concept, not a parse concept: the tail always looks structurally complete, and `complete` flags on code/math (`node.fenceClosed`, `node.mathClosed`) carry the real "is this still growing" bit.
- `renderHtml: false` + `mode` mapping in `toBlock()` means patchmark's `BlockKind` AST is used **only** for classification (is this code? mermaid? what language? is it complete?) and for `defs` carry-over; the `kind.inlines` AST is dead weight for the web UI. `renderBlocksToHtml` (patchmark/src/html.ts) is exported but unused by session-ui.

### Gaps
- `internalBlockMode`, `conceal`, and table-grid rendering on the TUI side are handled inside `@opentui/core` (not vendored here), so exact fence/paragraph splitting on the terminal cannot be verified from this repo.
- `holdPendingMarkers: false` in session-ui means a bare `##` *can* still render for a frame as an empty heading; the codebase compensates with `settleOnComplete: false` (the tail block is not frozen), but no test in `session-ui` asserts a zero-pop guarantee.

## Q3. How `marked` is configured

### Takeaway
`marked` is created in **`packages/ui/src/context/marked-parser.tsx`** (`createMarkdownParser()`), built on **`packages/ui/src/context/marked-base.tsx`** (`createMarkdownBase()` → `new Marked({ renderer: { link } })`). Apart from a custom `link` renderer, a `code` renderer (pierre highlights) and three KaTeX extensions, **no options object is passed at all** — so marked's defaults apply: `gfm: true`, `breaks: false`, `pedantic: false`, `async: false`. There are **no header ids and no mangle** because those options were removed from marked in v8; the repo pins `marked: 18.0.11`.

## Q4. KaTeX integration

### Takeaway
KaTeX is a **marked extension set** (`markdownMath`) defined in `packages/ui/src/context/marked-parser.tsx` and executed inside the markdown worker. Three tokenizers: `inlineDollarKatex` (handles both `$…$` and `$$…$$` in one regex, `displayMode` = "matched the `$$` branch"), `inlineParenKatex` (`\(…\)`), and block-level `blockKatex` (a `$$`/`$` line, then content, then the same delimiter line). All three funnel into one renderer: `katex.renderToString(token.text, { throwOnError: false, displayMode })`. Patchmark independently mirrors the same regexes so its *healed* text agrees with what KaTeX will see; its own HTML renderer emits inert `<span class="math-inline">` placeholders instead of KaTeX (unused in the web UI).

### Cited Findings
- `function renderMath(token: Tokens.Generic) { return katex.renderToString(token.text, { throwOnError: false, displayMode: token.displayMode }) }` — `throwOnError: false` means invalid TeX renders KaTeX's red error markup rather than throwing — [marked-parser.tsx#L40-L42](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/ui/src/context/marked-parser.tsx#L40-L42)
- **Dollar rules (Pandoc currency heuristic):** `const inlineDollarMathRegex = /\$\$(?!\$)((?:\\.|[^\\\n])*?(?:\\.|[^\\\n$]))\$\$|\$(?=[^\s$])((?:\\.|[^\\\n$])*?(?:\\\S|[^\s\\$]))\$(?!\w)/y` with the comment "`$$...$$` renders as display math anywhere in a line. `$...$` follows Pandoc's boundaries so prices and shell variables stay text: the opening `$` needs a non-space after it, the closing `$` needs a non-space before it and no letter, digit, or underscore after it. - KaTeX runs **per block**, inside the worker's `parser.parse()` — so a live block re-renders its math on every delta in which its text changes, but a settled block never does (`getReadyMarkdown`/LRU cache by content checksum).

- No measurement of KaTeX cost on very long formulas, and no explicit KaTeX size cap on the web side. (The **terminal** LaTeX renderer does have caps — see Q7/Q8.)

## Q5. DOMPurify configuration

### Takeaway
One private purifier instance lives in **`packages/session-ui/src/components/markdown-cache.tsx`**, configured **once** via `setConfig` (not per call), with an html+mathml profile, `style` tags forbidden, `svg`/`path` explicitly added for Mermaid, and two hooks: `beforeSanitizeAttributes` turns local file `href`/`src` into inert `data-local-link`/`data-local-image` attributes, and `afterSanitizeAttributes` hardens `target="_blank"` links with `noopener noreferrer`. - DOMPurify's exact default `ALLOWED_URI_REGEXP` is not overridden here, so the effective protocol list is DOMPurify's default; I did not verify it against a specific DOMPurify 3.4.17 build (not vendored in the repo).
- `ADD_TAGS: ["svg","path"]` is for Mermaid, but Mermaid SVG is injected via `diagram.innerHTML = view.svg` **after** sanitisation (see Q6), i.e. it bypasses DOMPurify; the safety argument there is that the SVG comes from `pele`, not from the model's HTML.

## Q6. `markdown-mermaid.ts`, `markdown-inline-code-kind.ts`, `markdown-clipboard.ts`

### Takeaway

## Q8. Large code blocks, timeouts, and plain-text fallbacks

### Takeaway
There is **no explicit size cap** on a single markdown block or code fence in the web UI. Robustness comes from four mechanisms instead: (1) a persistent parser that is linear-time by construction and fuzz-tested; (2) a worker with a watchdog (15 s no-progress, 60 s cold boot), exponential retry, and per-key request coalescing; (3) an LRU markdown cache plus a 200-entry highlight-stream cap; (4) multiple **fail-soft** layers that end in escaped plain text (`escape()` + `<br>`) rather than a broken/blank message. The terminal side is the one place with hard numeric limits (LaTeX: 100 000 chars / 256 nesting levels) and it falls back to showing the raw fenced source.

### Cited Findings
- **Plain-text fallback for prose.** `function fallback(markdown) { return escape(markdown).replace(/\r\n?/g, "\n").replace(/\n/g, "<br>") }`, used for (a) server-side rendering, (b) `initialResult` when no block is ready and `deferUntilReady` is false, (c) `pendingBlocks` for a live block before its render lands, and (d) the `catch` arm of the whole render pipeline — [markdown.tsx#L110-L121, L676-L717, L965-L983, L1163-L1200](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/components/markdown.tsx#L1163-L1200)
- **Plain-text fallback for code.** If highlighting fails with anything other than the three "expected" worker errors, it logs and degrades to a single unstyled token: `const fallbackToken: MarkdownToken = [text, ""]` → `{ stable: [], unstable: [fallbackToken] }`; the same shape is used in `pendingBlocks` for a code block whose tokens haven't arrived — [markdown.tsx#L123-L145](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/components/markdown.tsx#L123-L145)
- **Worker watchdog constants.** `WORKER_HANG_TIMEOUT_MS = 15_000` ("The worker fails when the oldest request in flight makes no progress across one whole window"), `WORKER_BOOT_TIMEOUT_MS = 60_000` ("covers loading its bundle and first grammar over a slow link"), `WORKER_RETRY_DELAY_MS = 2_000` doubling to `WORKER_RETRY_MAX_DELAY_MS = 60_000`, `HIGHLIGHT_STREAM_LIMIT = 200` — [markdown-worker-machine.ts#L12-L24, L463-L472, L491](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/components/markdown-worker-machine.ts#L12-L24)
- **Worker can be replaced on demand.** `createMarkdownWorkerClient(spawn)` with `spawn = () => new Worker(new URL("./markdown.worker.ts", import.meta.url), { type: "module" })`; effects `spawn-worker`, `close-worker` (`worker.terminate()`), `arm-watchdog`, `schedule-retry`; failures are typed `MarkdownWorkerDisposedError` / `MarkdownWorkerSupersededError` / `MarkdownWorkerUnavailableError` — [markdown-worker.ts#L40-L135, L224-L236](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/components/markdown-worker.ts#L224-L236)

- **Other truncation limits exist in adjacent UI** (not markdown): timeline diff review caps at `MAX_DIFF_CHANGED_LINES = 500`, shell output has backoff/retry constants, user messages fold at `max-height: …lh`. Markdown itself has none — [session-review-machine.ts#L1](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/components/session-review-machine.ts#L1); [shell-output-machine.ts#L6-L12](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/tools/shell-output-machine.ts#L6-L12)

### Inferences
- The design bets that a **linear-time block parser + worker watchdog** beats a magic size limit: a pathological 5 MB answer will still stream, and if `marked` wedges, the watchdog terminates the worker and the text degrades to escaped `<br>` output, then a fresh worker is spawned after a 2 s backoff.
- Because sanitisation happens inside the worker-settle callback in `markdown-cache.tsx` while the *worker* itself posts raw marked HTML, a sanitisation failure surfaces as `parse.failed` for that block group, which lands in the same `fallback()` path — one bad block can therefore degrade a whole answer to plain text, not just itself.

### Gaps
- I found **no** size threshold, line-count cap, or "collapse after N lines" for fenced code in `session-ui` (searched for `max-height`, `MAX_`, `truncat*` across the package). If such a guard exists it is in CSS outside `markdown.css` or in the timeline, not in the renderer.
- Whether `LiveTokenizer` (pierre 0.2.0) has its own line/text limits is not verifiable from this repo.
- `renderHtml: true` (patchmark's own HTML pipeline) is unused by session-ui, so its behaviour under large inputs is untested by the product path.

## Bonus (context the report may need): how sources are derived from tool calls

### Takeaway
Sources are **not** parsed out of assistant prose. `packages/session-ui/src/sources/sources.ts` walks the assistant tool parts of one turn, turns `websearch` into a `search` step (parsing `## [title](url)` lines out of the tool's *text* output) and `webfetch` into a `fetch` step, and dedupes by a scheme/www/slash/fragment-insensitive identity.

### Cited Findings
- Public shape: `turnSources(messages)` → `{ steps, sources }`, where `sources` is "Distinct sources in the order the turn met them: search results and opened pages, deduped by URL" — [session-ui/src/sources/sources.ts#L24-L47](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/sources/sources.ts#L24-L47)
- Only completed/failed tool parts count (`if (content.type !== "tool" || content.state.status === "streaming") return []`), and only `websearch` / `webfetch` are considered — [sources.ts#L64-L87](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/sources/sources.ts#L64-L87)
- The websearch contract: "The websearch tool keeps its structured results out of the message and writes each one as a `## [title](url)` heading in its text content (packages/core/src/tool/plugin/websearch.ts); a result without a title repeats its URL." Parsing is `line.startsWith("## [") && line.endsWith(")")` + `lastIndexOf("](")` — [sources.ts#L100-L118](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/sources/sources.ts#L100-L118)
- Hard gate on protocols: `if (parsed.protocol !== "https:" && parsed.protocol !== "http:") return undefined`; presentation splits `site` (hostname without `www.`) from `host` (full hostname, where the favicon lives) — [sources.ts#L120-L128](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/sources/sources.ts#L120-L128)
- Dedupe identity: ``return `${parsed.hostname.replace(/^www\./, "")}${parsed.pathname.replace(/\/+$/, "")}${parsed.search}` `` — "One source per page: the scheme, `www.`, a trailing slash and the fragment don't make another." — [sources.ts#L130-L135](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/sources/sources.ts#L130-L135)
- Favicons in rendered markdown are separate and hosted at Google: ``image.src = `https://www.google.com/s2/favicons?domain=${encodeURIComponent(url.host)}&sz=32` ``, skipped for private/special-use suffixes (`.internal`, `.local`, `.localhost`, `.test`, `.onion`, … and `home.arpa`) and replaced by a built-in GitHub glyph for `github.com` — [markdown.tsx#L467-L505](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/session-ui/src/components/markdown.tsx#L467-L505)

### Inferences
- Citation UI and source attribution are decoupled from rendering: the model's inline links are rendered by marked like any other link (with `external-link` class + favicon), while the "Sources" chip is computed from tool I/O, so a hallucinated inline link never becomes a source.

### Gaps
- `packages/core/src/tool/plugin/websearch.ts` was outside the sparse checkout, so the `## [title](url)` format is verified only from the consumer's comment and parser, not from the producer.
